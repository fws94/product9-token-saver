# Governance and maintenance

## Current maintainer

The repository is maintained by [@fws94](https://github.com/fws94). Contributors are welcome; public review and participation do not automatically grant repository permissions.

## How decisions are made

Use issues for scope, trade-offs and proposals, and pull requests for reviewable changes. Maintainers decide what is merged based on correctness, usefulness, compatibility and maintenance cost. Record significant decisions in the relevant issue or PR so others can understand them later.

Contributors should use branches and pull requests. Maintainers may make small direct maintenance or project-bootstrap updates; normal feature work should be reviewed through a PR. Opening a PR, creating an issue or using an agent does not itself authorize a merge.

No response or release timetable is guaranteed. If a change is waiting, a concise follow-up with new information is more helpful than repeated requests.

## Responsibilities

- Keep documentation honest about implemented, experimental and planned behavior.
- Preserve evidence when reporting performance or token savings.
- Review changes for portability, reproducibility and user data handling.
- Keep issue status and release notes aligned with delivered behavior.
- Treat contributors according to the [Code of Conduct](CODE_OF_CONDUCT.md).

Additional maintainers may be invited based on sustained contributions and willingness to review and maintain the project. Record role changes here. Release automation, package publishing and support commitments should be added only when the corresponding capability is actually established.
